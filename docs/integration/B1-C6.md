# Contrato de Integración: Analytics (Célula B1) <-> Célula C6

## 1. Información General
- **Módulo:** Analytics - Central Tendency
- **Consumidor:** C6 (Frontend - Exploración/Dashboard)
- **Versión:** 1.0.0

## 2. Endpoints que C6 debe consumir

### Tendencia central de una sección
- **Método:** `GET`
- **URL:** `/api/v1/analytics/sections/{id}/central-tendency`
- **Uso típico:** vista de detalle de sección (promedio, mediana y moda de todas sus notas).

### Tendencia central de un curso
- **Método:** `GET`
- **URL:** `/api/v1/analytics/courses/{id}/central-tendency`
- **Uso típico:** vista de exploración/curso completo (todas las secciones activas del curso).

## 3. Parámetros

| Parámetro | Ubicación | Tipo | Requerido | Aplica a | Descripción |
|---|---|---|---|---|---|
| `id` | Ruta | numérico, `id > 0` | Sí | ambos endpoints | Id de la sección o del curso. |
| `evaluationId` | Query | numérico, `> 0` | No | `/sections/{id}/...` | Limita el cálculo a una sola evaluación en vez de toda la sección. |
| `periodId` | Query | numérico, `> 0` | No | `/courses/{id}/...` | Limita el cálculo a un solo periodo académico en vez de todo el curso. |

Ejemplos:
```
GET /api/v1/analytics/sections/10/central-tendency
GET /api/v1/analytics/sections/10/central-tendency?evaluationId=45
GET /api/v1/analytics/courses/5/central-tendency
GET /api/v1/analytics/courses/5/central-tendency?periodId=2
```

## 4. JSON de Respuesta (HTTP 200)

```json
{
  "sampleSize": 5,
  "mean": 73.6,
  "median": 73.0,
  "mode": [70.0]
}
```

Cuando no hay calificaciones (sección/curso sin notas, o sin coincidencias para el
`evaluationId`/`periodId` solicitado), **no es un error**: responde igual HTTP 200
con el contrato estable:

```json
{
  "sampleSize": 0,
  "mean": null,
  "median": null,
  "mode": []
}
```

### Significado de cada campo

| Campo | Tipo | Significado |
|---|---|---|
| `sampleSize` | entero | Cantidad de calificaciones usadas en el cálculo. `0` si no hay notas; nunca es un error. |
| `mean` | número o `null` | Promedio aritmético de las notas. `null` solo cuando `sampleSize` es `0`. |
| `median` | número o `null` | Valor central de la distribución. `null` solo cuando `sampleSize` es `0`. |
| `mode` | lista de números | Valor(es) que más se repiten. Puede tener 0, 1 o varios valores (bimodal/multimodal). Lista vacía si no hay notas o si todas las notas tienen frecuencia 1. |

C6 debe tratar `mean`/`median` nulos y `mode` vacío como "sin datos suficientes
para graficar", no como un error de la petición.

## 5. Tratamiento recomendado de errores

Todos los errores usan el formato estándar U-Insight (mismo contrato que A5, B4
y C4): `{ timestamp, status, error, message, details, traceId }`.

```json
{
  "timestamp": "2026-10-10T21:30:00",
  "status": 404,
  "error": "RESOURCE_NOT_FOUND",
  "message": "La seccion 999 no existe",
  "details": [],
  "traceId": "b1-7f2e1c3a"
}
```

| HTTP | `error` | Cuándo ocurre | Qué debe hacer C6 |
|---|---|---|---|
| **400** | `VALIDATION_ERROR` | El `{id}` no es numérico, o `evaluationId`/`periodId` es inválido (≤ 0 o no numérico). | Error de uso/navegación propio del frontend (id mal formado en la URL); no reintentar automáticamente, revisar el link/parámetro que generó la petición. |
| **404** | `RESOURCE_NOT_FOUND` | La sección o el curso consultado no existe. | Mostrar "sección/curso no encontrado"; no es un error del sistema, es un dato inexistente. |
| **502** | `INTEGRATION_ERROR` | B1 no pudo comunicarse con A1, A4 o A6 (alguna célula caída o con error). | Mostrar "servicio no disponible, intenta más tarde"; es seguro reintentar pasado un momento. |
| **500** | `INTERNAL_SERVER_ERROR` | Error inesperado dentro de B1. | Mostrar error genérico; reportarlo (no es algo que el usuario pueda corregir). |

El campo `message` es legible para depuración/logs, pero **no debe mostrarse
tal cual al usuario final** — está pensado para desarrolladores, no para UI.
`traceId` sirve para correlacionar el reporte de un error con los logs del
backend si C6 necesita escalarlo.
